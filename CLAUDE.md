# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Development Commands

### Start the Bot
```bash
npm start
```
Uses ts-node to run the TypeScript entry point directly.

### Type Check
```bash
npm test
```
Runs TypeScript compiler with --noEmit flag to check for type errors without generating output files.

### Install Dependencies
```bash
npm install
```
Installs dependencies with npm-force-resolutions for dependency resolution.

### Update Scripts
```bash
# Windows
update.bat

# Linux/Mac
./update.sh
```

## Architecture Overview

### Core Entry Flow
- **Entry Point**: `index.ts` - Creates necessary directories and initializes the DiscordBot instance
- **Main Bot Class**: `src/structures/DiscordBot.js` - Extends Discord.Client with custom rustplus integration
- **Rust+ Integration**: `src/structures/RustPlus.js` - Rust+ connection through the Facepunch relay (`src/util/rustRelay.js`); game servers refuse direct connections since 2026-11-05
- **Connection Health**: `src/util/connectionManager.js` - Consolidated per-guild connection state machine (health checks, exponential-backoff reconnection, restart/wipe detection, watchdog). Replaces the former `connectionHealthMonitor.js` and `autoReconnectManager.js`, which have been deleted.

### Key Systems

#### Discord Integration
- Discord.js v14 with gateway intents for guilds, messages and members
- Slash command system in `src/commands/` with interaction handlers
- Event handlers in `src/discordEvents/` (ready, messageCreate, interactionCreate, etc.)
- Multi-language support via FormatJS internationalization in `src/languages/`

#### Rust+ API Integration
- FCM listeners (`src/util/FcmListener.js`) for push notifications from Rust+ companion app
- Relay websocket per guild (auth token from `/credentials add`; the bot warns in #activity when it is missing, expired or rejected)
- Smart device control (switches, alarms, storage monitors) via `src/handlers/`
- Protocol: `src/util/rustplus.proto`, the library's proto plus fields the official Rust+ web app uses (`kickFromTeam`, map note labels/icons, `camerasEnabled`, camera ray extras)
- Cameras (`src/handlers/cameraHandler.js`, `/camera`): own CCTV/PTZ/turret cameras by ID, only while the paired player is offline; monument cameras answer `access_denied` since 2026. The watched cameras get a message each in the cameras channel (`SetupCameras.js`, message ids in `instance.cameraMessageId`), refreshed every 5 minutes, every minute while the whole team is offline, plus a list of spotted non-team players (`serverList[].cameraSpotted`, last 25); strangers are also reported in #alerts while the whole team is offline
- Storage monitor loot alerts (`notifyIfLooted` in `src/rustplusEvents/message.js`): items leaving a monitored box while the whole team is offline, per-monitor `LOOT ALERT` toggle
- Alerts channel (`channelId.alerts`): smart alarm triggers (both paths), the Raid Alarm plugin push, camera sightings, loot and decay alerts, so #activity (team joins/deaths/AFK, trackers, server state, device not found) can be muted
- No map events or shops: Rust+ stopped sending those markers in August 2026, so those features were removed in v1.27.0

#### Data Management
- Instance-based configuration system with JSON files in `instances/` directory
- Credentials stored in `credentials/` directory (created at runtime)
- Static game data in `src/staticFiles/` (items.json, craftData, etc.)
- Winston logging system with logs stored in `logs/` directory

#### Enhanced Features (Fork-specific)
- **Item data**: `src/util/itemData/update.js`, a CLI run on a PC with Rust installed (`--rust-dir <Rust folder>`): item names/ids/stack sizes from the game files (`Bundles/items/*.json`), recipes/research/recycling from bobosneefdev/rust-items-json (MIT). rusthelp.com and wiki.rustclash.com block scripts, so there is no scraper. Commit `src/staticFiles` and rebuild the image after running it.
- **AI Assistant**: `src/util/ai/` - in-game `!ai` command and `/ai` Discord slash command
  - Works with any OpenAI-compatible chat completions endpoint (Ollama, OpenAI, OpenRouter, Gemini, ...)
  - Agentic tool loop (`tools.js`): the model can query live server data (team, server info, time, devices), search knowledge, and optionally toggle smart switches
  - Per-item knowledge JSONs in `AI/items/`, `AI/monuments/` and `AI/world/`, generated by `src/util/itemData/aiExport.js` at startup and on `/reloaddata` (gitignored)
  - Multi-turn conversation memory (`memory.js`) and optional smart-alarm AI alerts (`alerts.js`, opt-in via `RPP_AI_ALERTS_ENABLED`; one per raid: only the first trigger after 10 quiet minutes, and it reports team status from `get_team`, no advice)
  - Config in the `ai` block of `config/index.js`
- **Advanced Crafting System**: Comprehensive crafting calculations in `src/util/craftingCalculator.js`
- **Connection Management**: Robust reconnection system with health monitoring (`src/util/connectionManager.js`)
- **TypeScript Support**: Mixed JS/TS codebase with TypeScript entry point

### Important File Locations

#### Configuration
- `config/index.js` - Main configuration file
- `src/templates/` - Default settings templates
- `instances/{guildId}.json` - Per-server configuration (created at runtime)
- `credentials/{guildId}.json` - Authentication data (created at runtime)

#### Core Classes
- `src/structures/DiscordBot.js` - Main bot class with Discord and Rust+ integration
- `src/structures/RustPlus.js` - Rust+ API wrapper with game state management
- `src/structures/Items.js` - Item database management
- `src/structures/RustLabs.js` - Crafting and recipe data management

#### Handler Systems
- `src/handlers/inGameCommandHandler.js` - Processes commands from in-game chat
- `src/handlers/smartSwitchHandler.js` - Manages smart switch device control
- `src/handlers/storageMonitorHandler.js` - Monitors storage containers
- `src/handlers/trackerHandler.js` - Trackers: polls each tracked server's player list every minute via the free Steam server query (`src/util/serverQuery.js`), matches by name, refreshes Steam names every 5 minutes

### Environment Variables
- `RPP_DISCORD_CLIENT_ID` - Discord application client ID (required)
- `RPP_DISCORD_TOKEN` - Discord bot token (required)
- `RPP_STEAM_API_KEY` - Free Steam Web API key (optional); trackers use it to find a relay-paired server's address by name
- `RPP_AI_*` - AI assistant settings (optional). Authoritative list in the `ai` block of `config/index.js`: `RPP_AI_ENABLED`, `RPP_AI_BASE_URL`, `RPP_AI_API_KEY`, `RPP_AI_MODEL`, `RPP_AI_MAX_TOKENS`, `RPP_AI_TEMPERATURE`, `RPP_AI_TIMEOUT_MS`, `RPP_AI_TOOLS_ENABLED`, `RPP_AI_MAX_TOOL_ITERATIONS`, `RPP_AI_CONTROL_ENABLED`, `RPP_AI_KNOWLEDGE_DIR`, `RPP_AI_MEMORY_TURNS`, `RPP_AI_MEMORY_TTL_MS`, `RPP_AI_ALERTS_ENABLED`

### Development Notes
- The codebase is a mix of JavaScript and TypeScript
- Main entry is TypeScript (`index.ts`) but most logic is in JavaScript files
- Bot requires Rust+ credentials obtained via the companion app
- Each Discord server must be paired with a Rust game server
- Smart devices must be paired in-game before Discord control is available
- The bot keeps one relay connection per guild for polling and team chat

### Testing and Validation
- TypeScript type checking via `npm test`
- No traditional unit tests - validation happens through runtime type checking
- Bot functionality testing requires live Rust server connections

### Docker Support
Available via docker-compose.yml or direct docker run commands with proper environment variables.
